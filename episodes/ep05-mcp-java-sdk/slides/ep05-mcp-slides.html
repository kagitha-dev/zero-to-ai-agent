JSON-RPC 2.0 · the request

A request has just four fields

{  "jsonrpc": "2.0",  "method":  "subtract",  "params":  [42, 23],  "id":      1}
In plain English
"Please run subtract with 42 and 23.
This is request number 1."
jsonrpc
Version tag
Always exactly "2.0".
method
Which function to run
A name, like "subtract".
params
The inputs
Optional. An array or an object.
id
Request number
String or number. The answer comes back with the same id.
params · two styles
By position, or by name
By position (array): order matters
"params": [42, 23]
By name (object): order doesn't matter
"params": {"subtrahend": 23, "minuend": 42}
Both return 19. MCP always uses by name
REQUESTFour fields: version, method, params, id.
JSON-RPC 2.0 · the response

The answer comes back with the same id

it worked
{"jsonrpc": "2.0", "result": 19, "id": 1}
it failedwe asked for method "foobar"
{"jsonrpc": "2.0",
 "error": {"code": -32601,
           "message": "Method not found"},
 "id": "1"}
Three rules
1result or error. Never both.
2The id must match the request.
3Couldn't read the request at all? Then "id": null.
-32700Parse errorthe JSON is broken
-32600Invalid RequestJSON, but not a valid request
-32601Method not foundno such method
-32602Invalid paramswrong inputs
-32603Internal errorit broke on the server side
RESPONSEresult or error, plus the same id.
JSON-RPC 2.0 · id and notifications

The id pairs each answer with its question

Client
Waiting for answers
id 1subtract(42, 23)…
id 2sum(1, 2, 4)…
id 3get_data()…
no idupdate([1,2,3,4,5])no wait
Server
Doing the work
got id 1 · got id 2 · got id 3
finished id 3 first (fast one)
then id 1, then id 2
got "update" · no id
→ sends no reply (by design)
→ requests
← responses
[ {…, "id":1}, {…, "id":2} ]
Batch: JSON-RPC lets you send many requests in one array. MCP removed batching (version 2025-06-18), so you won't use it there.
REMEMBERWith an id: a request. Without an id: a notification, no reply.
